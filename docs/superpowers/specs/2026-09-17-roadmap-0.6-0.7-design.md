# Shortcut 0.6–0.7 Roadmap Design

## Goal

Build the next two product layers on top of the stable messaging/automation core without changing the existing media tools or App Usage Time behavior.

## Global constraints

- Native Android: Kotlin + Compose + Material3 only.
- No WebView.
- Local-first / offline-first for core data.
- No mandatory account or cloud dependency.
- Arabic/English with RTL/LTR.
- Request permissions only at the moment a feature needs them.
- No Accessibility Service in the normal Google Play release path.
- minSdk 26, targetSdk 36.
- Keep App Usage Time charts exactly at two charts.

## Shortcut 0.6 — Automation Engine

### Automation model

Introduce a local `AutomationRoutine` with stable ID, name, enabled state, trigger, ordered actions, and last-updated timestamp. Editing preserves the ID; duplication creates a new ID.

### Triggers

The first engine supports triggers that are feasible without Accessibility:

- scheduled time
- charger connected/disconnected
- battery threshold
- NFC tag/manual NFC dispatch
- device boot/package replaced restoration

Wi-Fi and Bluetooth triggers are exposed only where Android public APIs and runtime restrictions permit reliable detection. Device-unlock and arbitrary app-open triggers remain unavailable in the standard build if they require Accessibility or restricted background behavior.

### Actions

Initial routine actions reuse existing app capabilities instead of duplicating implementations:

- open installed app
- open URL
- open maps
- prepare WhatsApp message
- prepare Telegram message
- open a Shortcut tool
- show notification

Actions execute sequentially. If an action cannot execute in background because Android forbids bringing another app to foreground, the engine records a prepared/needs-user-action result and presents a notification.

### Routine execution

A routine execution receives a run ID and records each action result. The routine continues after non-fatal prepared outcomes, but stops after fatal validation/runtime failures unless the action explicitly allows continue-on-error.

### My Automations

Add a central list with Active, Paused, Upcoming and Failed/recent states. Each routine exposes Edit, Pause/Resume, Run now, Duplicate and Delete.

### Templates

Ship useful local templates, including morning apps, maps/commute, charging reminder, low-battery action, WhatsApp prepared message, Telegram prepared message, and app-usage shortcut.

## Shortcut 0.7 — System Integration + Portability

### Backup and restore

Create one portable local backup document containing scheduled shortcuts, scheduled messages, routines, favorites/recent tool preferences and app settings that are safe to transfer. Secrets such as Telegram bot tokens are excluded by default.

Use Storage Access Framework so the user chooses export/import destination. No broad storage permission is required.

### Import/export routines

Allow a single routine to be exported as a portable JSON document and imported after preview/validation. Import always creates a new local ID unless explicitly replacing the same exported ID after user review.

### Widgets

Add a lightweight home-screen App Widget with quick actions for Run routine, App usage, QR and recent/favorite tool. The widget must not execute restricted background actions silently; it launches the appropriate Shortcut flow when needed.

### Quick Settings tile

Add a Quick Settings tile that opens a configurable favorite Shortcut action/routine. The tile uses public Android tile APIs and no Accessibility.

### Dynamic app shortcuts

Publish a small set of launcher shortcuts for New automation, App usage, QR and the most recent/favorite tool.

### Search / command palette

Provide one local search surface over tools, scheduled automations, routines and templates. Search does not require network access.

### Home improvements

Home prioritizes Favorites, Recent tools, Upcoming automation and latest failure without overloading the screen.

### Media batch consistency

Where existing tools already accept multiple files, keep their behavior. Add batch affordances only to Resize/Compress/JPEG/ZIP through the existing media operation boundaries; do not rewrite stable PDF/OCR/GIF code.

### Undo and naming

Deletion of local automation entities offers a short Undo path. Builders derive a useful default name when the user leaves the name blank.

## Telegram position

Personal Telegram remains prepared-message mode unless an official TDLib feasibility review concludes GO. Telegram Bot API may be added as a separate advanced auto-send mode only if credentials are stored securely and UI clearly states the message is sent by a bot.

No private Telegram/WhatsApp intents, reverse-engineered hooks, simulated clicks, or Accessibility-based Send automation are allowed.

## Testing

All production behavior follows TDD. Required tests include routine codec round-trip, ordered action execution, stop/continue rules, trigger matching, pause/resume, import/export validation, backup exclusion of secrets, search matching, widget/tile routing helpers, and no-duplicate edit semantics.

CI must pass unit tests, lint, androidTest Kotlin compilation and debug APK assembly before completion.
