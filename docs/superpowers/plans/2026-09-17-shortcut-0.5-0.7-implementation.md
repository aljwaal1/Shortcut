# Shortcut 0.5–0.7 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Deliver stable editable scheduling, honest WhatsApp/Telegram messaging, a local multi-step automation engine, and Android system integrations/backup without Accessibility or cloud accounts.

**Architecture:** First stabilize identity/storage/scheduler boundaries, then build routines by composing existing actions, then add system integration surfaces that route into those boundaries. All external-app launches use notification/user-action fallbacks when Android background restrictions apply.

**Tech Stack:** Kotlin, Jetpack Compose, Material3, AlarmManager, BroadcastReceiver, SharedPreferences/DataStore where already used, Storage Access Framework, AppWidget/TileService, JUnit4.

**Spec:** `docs/superpowers/specs/2026-09-17-messaging-automation-core-design.md` and `docs/superpowers/specs/2026-09-17-roadmap-0.6-0.7-design.md`

## Global Constraints

- Native Kotlin + Compose + Material3; no WebView.
- Local-first core data; no mandatory account/cloud.
- Arabic/English RTL/LTR.
- No Accessibility Service in normal release.
- minSdk 26; targetSdk 36.
- Do not change App Usage Time data semantics or add charts beyond the existing two.
- Permissions only when the invoked feature needs them.
