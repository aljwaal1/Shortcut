# PDF Split Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans task by task; write tests before implementation.

**Goal:** Export ordered single-page PDFs and reviewable automatic/manual chapter PDFs to named SAF subfolders.

**Architecture:** Pure Kotlin page-range model and suggestion normalization, plus one Android Activity using PdfBox and the Storage Access Framework. Add routes and bilingual tool catalog entry.

**Tech Stack:** Kotlin Android, PdfBox Android, Activity Result, DocumentsContract, JUnit.

**Spec:** `docs/superpowers/specs/2026-10-23-pdf-split-design.md`

## Global Constraints

- Android 8–16; no external permission for folder picking; keep the input untouched.
- Result names sorted first through last, `Pages` or `Chapters` inside source-specific folder.
- Chapter auto-detection is reviewable; editable manual fallback if no headings/bookmarks.

## Review Focus

- Single-page and encrypted PDFs: report meaningful errors or preserve a valid single-page file.
- Duplicate/unsorted outlines: normalize increasing page boundaries.
- Bad custom ranges: reject overlapping, out-of-bounds or empty output sets.
- Invalid SAF tree and cancellation: explain error without destroying previous results.
- Export interruption: preserve prior files and report partial output honestly.

**Interfaces:** `PdfSplitPlan.pages(count)`, `PdfSplitPlan.chapters(count, starts)` and `PdfSplitPlan.parseRanges(text,count)` return numbered ranges and validate boundaries.
